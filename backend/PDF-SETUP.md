# Form PDF deployment

Follow-up and family-session PDFs render the submitted HTML form in Chromium.
PDFKit is not a substitute for this layout. If rendering fails, completion returns
an error so the filled form stays open for retry.

Run from the backend directory during deployment:

```sh
npm ci
npm run pdf:install
```

Deploy `assets/fonts` and the `.cache/puppeteer` directory with the backend.
The runtime user must be able to read and execute the downloaded browser.
Build and run on the same OS/architecture; do not copy a Windows browser to Linux.

On a supported Debian/Ubuntu host missing browser system libraries, an administrator
can install them during deployment with:

```sh
npx puppeteer browsers install chrome --install-deps
```

Alternatively set `PDF_BROWSER_PATH` to an installed Chrome/Chromium executable.
Restart the backend after deployment. Check backend logs for the original browser
launch error if PDF generation still fails. Existing PDFKit-generated documents
must be regenerated by editing and saving the completed form again.
